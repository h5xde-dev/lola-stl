# lola.stl

Магазин авторских STL-моделей кашпо и боксов. Сейчас это прототип на Next.js:
каталог и страницы моделей рендерятся на сервере, оплата и скачивание имитируются.

## Запуск

Нужен Node.js 20.9 или новее.

```bash
npm install
npm run dev        # http://localhost:3000
```

Проверка рабочей сборки: `npm run build && npm start`.

## Что где

| Путь | Что это |
| --- | --- |
| `app/page.jsx` | Главная с каталогом. Рендерится на сервере при каждом запросе |
| `app/models/[slug]/page.jsx` | Страница модели: SEO-метаданные, товарные open-graph-теги, schema.org Product и хлебные крошки |
| `app/category/[slug]/page.jsx` | Страница категории: schema.org CollectionPage со списком товаров |
| `lib/schema.js` | Общая разметка: организация, сайт с поиском, товар |
| `app/models/[slug]/opengraph-image.jsx` | Картинка для соцсетей и мессенджеров с рендером модели |
| `app/sitemap.js`, `app/robots.js` | Карта сайта и правила для поисковиков |
| `app/cart`, `app/checkout`, `app/purchases` | Корзина, оформление, «Мои покупки» (закрыты от индексации) |
| `app/admin` | Админка прототипа: модели, категории, цены и акции, промокоды, наборы, заказы с журналом скачиваний |
| `lib/models.js` | Категории и модели. `getModels()`, `getCategories()` и др. потом будут читать базу данных |
| `lib/pricing.js` | Расчёт цены: «2+1», «1+1», боксы, наборы, промокоды, скидка постоянным, раскладка по чеку. Тесты: `npm test` |
| `docs/oplata-skidki-zashchita.md` | Схема оплаты (ЮKassa), выдачи файлов по ссылкам с лимитами и скидок — по ней делается рабочий бэкенд |
| `components/ModelArt.jsx` | Схема модели в SVG, пока нет фото. Рисуется на сервере |

Правки из админки прототипа хранятся в браузере (localStorage). Модели, добавленные там,
открываются по ссылке с `?local=1`. Поисковики увидят их только после подключения базы.

## SEO и индексация

По умолчанию сайт закрыт от поисковиков: `robots.txt` запрещает всё, на страницах стоит `noindex`.
Это сделано специально, пока в подвале заглушки реквизитов ИП.

Чтобы открыть сайт, задайте переменные окружения в Vercel (Settings → Environment Variables):

| Переменная | Значение |
| --- | --- |
| `NEXT_PUBLIC_SITE_URL` | Основной адрес, например `https://lola-stl.ru`. Без неё берётся адрес проекта на Vercel |
| `INDEXING` | `on`: открыть индексацию и отдать sitemap в `robots.txt` |
| `NEXT_PUBLIC_DEMO` | `off`: скрыть верхнюю панель прототипа |
| `GOOGLE_SITE_VERIFICATION` | код подтверждения из Google Search Console |
| `YANDEX_VERIFICATION` | код подтверждения из Яндекс Вебмастера |
| `NEXT_PUBLIC_SAME_AS` | ссылки на соцсети через запятую, например Telegram-канал: попадут в разметку организации |

После этого добавьте сайт в Яндекс Вебмастер и Google Search Console и отправьте `/sitemap.xml`.

## Рабочий режим: оплата, файлы, почта

Без настроек сайт работает в режиме проверки — весь путь покупки проходит, но ничего не уходит наружу:

| Что | Без настроек | Рабочий режим |
| --- | --- | --- |
| База | встроенный Postgres в `.data/` (на Vercel — временный, заказы пропадают) | `DATABASE_URL` |
| Оплата | тестовая страница `/pay/mock/…` | `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` |
| Файлы моделей | папка `.data/files` | `S3_*` — закрытый бакет |
| Письма | только журнал в админке → «Письма» | `SMTP_URL` |
| Telegram | без входа и сообщений | `TELEGRAM_BOT_TOKEN` |

Все переменные с пояснениями — в [.env.example](.env.example). Что подключено, видно в админке → «Письма» → «Подключённые сервисы».

**Порядок запуска продаж:**
1. Создайте базу Postgres (например, Neon — бесплатный тариф) и задайте `DATABASE_URL`. Таблицы и каталог создадутся сами при первом запуске.
2. Задайте `AUTH_SECRET` (`openssl rand -base64 32`), `ADMIN_PASSWORD` и `NEXT_PUBLIC_SITE_URL`.
3. Хранилище: Yandex Object Storage → закрытый бакет, сервисный аккаунт с правом записи, статический ключ → `S3_*`. Затем загрузите STL каждой модели в админке (редактор модели → «STL-файл»).
4. ЮKassa: в личном кабинете возьмите shopId и секретный ключ (сначала тестового магазина), подключите «Чеки от ЮKassa». В разделе HTTP-уведомлений укажите `https://<домен>/api/yookassa/webhook`, события `payment.succeeded` и `payment.canceled`.
5. Почта: SMTP-доступ почтового ящика домена или сервиса рассылок → `SMTP_URL`.
6. Telegram: бот у @BotFather → `TELEGRAM_BOT_TOKEN`, в настройках бота — Mini App с адресом сайта.

**Как устроена защита файлов:** файлы лежат в закрытом хранилище. «Скачать» выдаёт ссылку на 5 минут только покупателю этого заказа и пишет журнал (IP, устройство). Лимит — 5 скачиваний модели, больше 3 разных сетей за сутки — заказ встаёт «на проверку». Владелица видит журнал, сбрасывает лимит, закрывает или открывает доступ в разделе «Заказы». Подробная схема — [docs/oplata-skidki-zashchita.md](docs/oplata-skidki-zashchita.md).

**Проверка локально в рабочей сборке:** `AUTH_SECRET=test ADMIN_PASSWORD=lola npm run build && npm start`. В режиме разработки (`npm run dev`) пароль админки — `lola`.

## Деплой на Vercel

1. Отправьте репозиторий на GitHub: `git push -u origin main`.
2. На vercel.com: **Add New → Project → Import** этого репозитория. Vercel сам определит Next.js, настройки менять не нужно.
3. Каждый пуш в `main` будет публиковаться автоматически.
