# lola.stl

Магазин авторских STL-моделей кашпо и боксов. Сейчас это прототип на Next.js:
каталог и страницы моделей рендерятся на сервере, оплата и скачивание имитируются.

## Запуск

Нужен Node.js 20.9 или новее.

```bash
npm install
npm run dev        # http://localhost:3000
```

Проверка рабочей сборки: `npm run build && npm start`.

## Что где

| Путь | Что это |
| --- | --- |
| `app/page.jsx` | Главная с каталогом. Рендерится на сервере при каждом запросе |
| `app/models/[slug]/page.jsx` | Страница модели: SEO-метаданные, товарные open-graph-теги, schema.org Product и хлебные крошки |
| `app/category/[slug]/page.jsx` | Страница категории: schema.org CollectionPage со списком товаров |
| `lib/schema.js` | Общая разметка: организация, сайт с поиском, товар |
| `app/models/[slug]/opengraph-image.jsx` | Картинка для соцсетей и мессенджеров с рендером модели |
| `app/sitemap.js`, `app/robots.js` | Карта сайта и правила для поисковиков |
| `app/cart`, `app/checkout`, `app/purchases` | Корзина, оформление, «Мои покупки» (закрыты от индексации) |
| `app/admin` | Админка прототипа: модели, категории, цены и акции, промокоды, наборы, заказы с журналом скачиваний |
| `lib/models.js` | Категории и модели. `getModels()`, `getCategories()` и др. потом будут читать базу данных |
| `lib/pricing.js` | Расчёт цены: «2+1», «1+1», боксы, наборы, промокоды, скидка постоянным, раскладка по чеку. Тесты: `npm test` |
| `app/blog`, `lib/md.jsx` | Статьи: список и страница статьи с разметкой BlogPosting; текст в простой разметке (заголовки, списки, фото, карточки моделей) |
| `app/account`, `app/o/[token]` | Личный кабинет; постоянная личная ссылка на каждый заказ и печатный чек `/o/<ссылка>/receipt` |
| `app/admin/analytics`, `lib/server/analytics.js` | Аналитика заказов: выручка, средний чек, конверсия, модели, категории, каналы, промокоды |
| `app/admin/home`, `app/admin/seo`, `lib/content.js` | Картинки и тексты главной, SEO сайта, реквизиты продавца |
| `lib/server/media.js` | Картинки из админки: `.data/media`, отдаются по `/media/<файл>` и сжимаются next/image |
| `docs/oplata-skidki-zashchita.md` | Схема оплаты (ЮKassa), выдачи файлов и скидок (первоначальный план; лимиты скачиваний потом убраны — файлы выдаются по уникальной ссылке заказа) — по ней делается рабочий бэкенд |

Правки из админки прототипа хранятся в браузере (localStorage). Модели, добавленные там,
открываются по ссылке с `?local=1`. Поисковики увидят их только после подключения базы.

## SEO и индексация

По умолчанию сайт закрыт от поисковиков: `robots.txt` запрещает всё, на страницах стоит `noindex`.
Это сделано специально, пока в подвале заглушки реквизитов ИП.

Чтобы открыть сайт, задайте переменные окружения в файле `.env` на сервере:

| Переменная | Значение |
| --- | --- |
| `SITE_URL` | Основной адрес, например `https://lola-stl.ru` |
| `INDEXING` | `on`: открыть индексацию и отдать sitemap в `robots.txt` |
| `DEMO` | `off`: скрыть верхнюю панель прототипа |
| `GOOGLE_SITE_VERIFICATION` | код подтверждения из Google Search Console |
| `YANDEX_VERIFICATION` | код подтверждения из Яндекс Вебмастера |
| `SAME_AS` | ссылки на соцсети через запятую, например Telegram-канал: попадут в разметку организации |

После этого добавьте сайт в Яндекс Вебмастер и Google Search Console и отправьте `/sitemap.xml`.

## Рабочий режим: оплата, файлы, почта

Без настроек сайт работает в режиме проверки — весь путь покупки проходит, но ничего не уходит наружу:

| Что | Без настроек | Рабочий режим |
| --- | --- | --- |
| База | встроенный Postgres в `.data/` (только для проверки) | `DATABASE_URL` |
| Оплата | тестовая оплата (включается в админке → «Оплата») | `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` |
| Файлы моделей | папка `.data/files` | `S3_*` — закрытый бакет |
| Письма | только журнал в админке → «Письма» | `SMTP_URL` |
| Telegram | без входа и сообщений | `TELEGRAM_BOT_TOKEN` |

Все переменные с пояснениями — в [.env.example](.env.example). Что подключено, видно в админке → «Письма» → «Подключённые сервисы».

**Порядок запуска продаж:**
1. База: на своём сервере Postgres запускается в Docker вместе с сайтом (см. «Запуск на сервере»), `DATABASE_URL` задаёт compose. Таблицы и каталог создадутся сами при первом запуске.
2. Задайте `AUTH_SECRET` (`openssl rand -base64 32`), `ADMIN_LOGIN`, `ADMIN_PASSWORD` и `SITE_URL`. Вход в админку — по логину и паролю, не больше 5 неудачных попыток за 15 минут с одного адреса; смена пароля на сервере сразу завершает все старые входы. Ссылок на админку на сайте нет — адрес знает только владелица.
3. Хранилище: закрытый бакет в Timeweb Cloud или Yandex Object Storage, ключ доступа с правом записи → `S3_*`. В настройках бакета:
   - **CORS** — разрешить загрузку из админки: источник `https://<домен>`, методы `PUT` и `GET`, заголовки `*`;
   - **правило жизненного цикла** — удалять незавершённые загрузки частями через 7 дней (если загрузку бросили на середине).

   Затем загрузите STL или ZIP каждой модели в админке (редактор модели → «STL-файл»).
4. ЮKassa: в личном кабинете возьмите shopId и секретный ключ (сначала тестового магазина), подключите «Чеки от ЮKassa». В разделе HTTP-уведомлений укажите `https://<домен>/api/yookassa/webhook`, события `payment.succeeded` и `payment.canceled`.
5. Почта: SMTP-доступ почтового ящика домена или сервиса рассылок → `SMTP_URL`.
6. Telegram: бот у @BotFather → `TELEGRAM_BOT_TOKEN`. Когда сайт доступен по HTTPS, одна команда настроит бота — кнопку меню «Магазин», ответ на /start кнопкой «Открыть магазин», команды и описание:
   `TELEGRAM_BOT_TOKEN=… SITE_URL=https://<домен> AUTH_SECRET=<как у сайта> npm run tg:setup`.
   Внутри Telegram сайт сам переходит в вид мини-приложения: на весь экран, шапка в цвет сайта, системная кнопка «Назад», вход по подписи Telegram без пароля. После оплаты бот присылает кнопку «Открыть покупки».

**Способы оплаты** включаются и выключаются в админке → «Оплата»: СБП, карта, SberPay, T-Pay (через ЮKassa — видны покупателям, только когда заданы ключи ЮKassa) и **тестовая оплата** без денег. Тестовую можно включить «только мне» (видна в браузере, где открыта админка — безопасно на работающем сайте) или «всем посетителям» (для показа магазина). Тестовые заказы помечаются, не входят в аналитику, не дают скидку постоянного и удаляются одной кнопкой. Переменная `ALLOW_TEST_PAYMENTS=on` по-прежнему открывает тестовую оплату всем — для автопроверок.

**Личный кабинет и ссылки на заказы.** У каждого заказа своя постоянная личная ссылка `/o/<код>`: она приходит в письме и от бота, открывает заказ на любом устройстве сколько угодно раз и ведёт на печатный чек. В личном кабинете (`/account`) — все заказы покупателя со ссылками и чеками; вход — по ссылке на email (3 дня) или через Telegram, после входа кабинет открыт 90 дней. Фискальные данные чека (ФН, ФД, ФП) подтягиваются из ЮKassa при первом открытии чека.

**Как устроена защита файлов:** файлы лежат в закрытом хранилище и выдаются только по уникальной ссылке заказа или из личного кабинета покупателя — без ограничения числа скачиваний. «Скачать» даёт ссылку на файл на 5 минут, имя файла содержит номер заказа, каждое скачивание пишется в журнал (IP, устройство). Владелица видит журнал, может закрыть или снова открыть доступ к заказу и отправить ссылку на заказ ещё раз в разделе «Заказы».

**Проверка локально в рабочей сборке:** `AUTH_SECRET=test ADMIN_LOGIN=lola ADMIN_PASSWORD=lola npm run build && npm start`. В режиме разработки (`npm run dev`) логин и пароль админки — `lola` / `lola`.

## Запуск на сервере с 2 ГБ памяти

Сайт работает в Docker: **сайт + Postgres + Caddy** (HTTPS с автоматическим сертификатом). Проект **не собирается на сервере** — образ собирает GitHub Actions при каждом пуше в `main` и публикует в `ghcr.io`, сервер только скачивает и запускает его. Сборка Next.js требует 1–1,5 ГБ памяти, а работающему сайту хватает около 100 МБ.

**Память, замер под нагрузкой** (страницы, обработка фото в 4 размерах, промокоды — 420 запросов, 20 параллельно):

| Контейнер | Лимит | Пик |
| --- | --- | --- |
| Сайт (Next.js, standalone) | 512 МБ | 102 МБ |
| Postgres 16 | 320 МБ | 30 МБ |
| Caddy | 96 МБ | ~20 МБ |
| Система Ubuntu | — | ~250 МБ |
| **Итого** | | **≈ 400 МБ из 2 ГБ** + 1 ГБ swap про запас |

**Процессор, замер на одном ядре** (контейнер ограничен 1 vCPU, 10 одновременных посетителей):

| Запрос | CPU на запрос | Скорость |
| --- | --- | --- |
| Главная, страница модели, категория | ~3,3 мс | ~280 стр/с |
| Картинка для соцсетей (из кеша) | ~3,5 мс | ~170 шт/с |
| Цена корзины, «Мои покупки» (API) | ~2,5 мс | ~280 запр/с |
| Фото (из кеша) | ~2 мс | ~200 шт/с |

Одного ядра хватает с большим запасом: 280 страниц в секунду — это больше 20 млн страниц в сутки. Нагрузку снимают три кеша:
- **готовые страницы (ISR)** — каталог одинаковый для всех, корзина и покупки работают в браузере. Сохранение в админке сразу сбрасывает кеш, после запуска сервера кеш тоже обновляется;
- **данные каталога в памяти** — до 30 секунд, сбрасываются при сохранении в админке;
- **картинки для соцсетей и шрифты** — рисуются один раз (~0,3 с CPU) и дальше отдаются из памяти, браузерам и мессенджерам — на сутки.

**Что сделано для экономии памяти:** сборка в CI; режим `standalone` (в образе 80 МБ кода вместо 460 МБ `node_modules`); потолок памяти Node.js 320 МБ; обработка фото в один поток, только WebP, 4 размера и кеш на 30 дней; Postgres настроен под маленький сервер; лимиты памяти на каждый контейнер.

**Первый запуск:**
1. Сервер Ubuntu 22.04/24.04, 1 vCPU, 2 ГБ RAM, 20–30 ГБ NVMe. DNS: A-запись домена на IP сервера.
2. На сервере от root: `bash setup-server.sh` (из папки [deploy](deploy)) — swap 1 ГБ, Docker, брандмауэр.
3. Скопируйте в `/opt/lola-stl` файлы [deploy/docker-compose.yml](deploy/docker-compose.yml), [deploy/Caddyfile](deploy/Caddyfile) и `.env` по образцу [deploy/.env.example](deploy/.env.example).
4. `docker login ghcr.io` (логин GitHub и токен с правом `read:packages`), затем `docker compose up -d`. Таблицы и каталог создадутся сами.
5. Резервные копии базы: `deploy/backup.sh` в cron, раз в сутки.
6. Автовыкладка: в GitHub → Settings → Secrets and variables → Actions добавьте `SSH_HOST`, `SSH_USER`, `SSH_KEY`. После этого каждый пуш в `main` сам обновляет сайт.

Адрес сайта, индексация и панель прототипа задаются переменными `SITE_URL`, `INDEXING`, `DEMO` при запуске — пересобирать образ для смены домена не нужно.

**Большие файлы (250 МБ и больше).** Загрузка из админки не нагружает сервер:
- **с S3** файл режется на части по 16 МБ, три части летят параллельно прямо в хранилище, каждая при сбое повторяется. Оборвался интернет или закрыли вкладку — выберите тот же файл снова, загрузка продолжится с места остановки. Сервер сайта только выдаёт ссылки на части и собирает файл; скачивания покупателей тоже идут напрямую из хранилища;
- **без S3** файл пишется на диск сервера потоком.

Замер на файле 600 МБ: с S3 — память сайта 72 МБ, файл собран из частей после «обрыва» на середине и скачан покупателем побайтно без изменений; без S3 — 75 МБ, запись 5 секунд. Лимит — 5 ГБ на файл. Заменённые файлы удаляются из хранилища автоматически.

**Проверка образа локально:** `docker build -t lola-stl:test .`, затем `docker compose up -d app db` в папке с compose-файлом и `.env` (`APP_IMAGE=lola-stl:test`) и `BASE_URL=http://localhost:3000 npm run e2e` (сервер с `ADMIN_LOGIN=lola ADMIN_PASSWORD=lola DEMO=off`).
